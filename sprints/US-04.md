# US-04: Thêm / sửa / xoá sản phẩm với ảnh flat lay (Admin)

## Bối cảnh
- Epic: Quản lý kho hàng (Epic 2).
- Vai trò: Admin.
- Mục tiêu: Thêm sản phẩm (tên, giá, danh mục, ảnh trải phẳng – flat lay) để hiển thị cho khách và làm đầu vào cho thử đồ GenAI (Epic 3); sửa, xoá khi cần.

## Phạm vi
- Danh sách sản phẩm (ảnh thu nhỏ, tên, giá, danh mục), lọc theo danh mục.
- Thêm sản phẩm kèm đúng 1 ảnh flat lay; sửa thông tin và thay ảnh (tuỳ chọn); xoá sản phẩm (xoá luôn ảnh trong Storage).
- Ảnh lưu bucket private `products`, client nhận signed URL.
- API đọc cho người mua (Task 7): sản phẩm theo danh mục, cần đăng nhập.
- Ngoài phạm vi: ẩn/hiện sản phẩm, nhiều ảnh/biến thể (size, màu), tồn kho, tìm kiếm, phân trang, kiểm tra tỷ lệ ảnh flat lay (chỉ kiểm tra kích thước tối thiểu 400×400 px).
- Thiết kế chi tiết: `design/flows/product-management.md`; bảng/bucket `design/database/schema.md` mục 11–12.

## Luồng chính (happy path)
- Admin vào `/admin/products` → client gọi `GET /api/admin/categories` và `GET /api/admin/products` → hiển thị danh sách (mới nhất trước), chọn bộ lọc danh mục → `?categoryId=`.
- Thêm: "Thêm sản phẩm" → `/admin/products/new` → nhập tên, giá, chọn danh mục, chọn ảnh (xem trước) → Lưu → `POST` multipart → 201 → về danh sách, toast "Đã lưu sản phẩm."
- Sửa: "Sửa" → `/admin/products/:id/edit` (`GET /:id`) → đổi trường và/hoặc chọn ảnh mới → Lưu → `PUT` multipart → 200; ảnh cũ bị xoá khỏi Storage khi thay thành công.
- Xoá: "Xoá" → xác nhận → `DELETE /:id` → 200 → bỏ khỏi danh sách; ảnh bị xoá khỏi Storage.

## Luồng lỗi cần xử lý
- 401 → `/login?redirect=…`; user thường → 403.
- Thiếu/ sai tên, giá, danh mục, thiếu ảnh khi thêm → 400 `VALIDATION_ERROR` với `fields` (hiện mọi lỗi cùng lúc).
- Danh mục không tồn tại (bị xoá trong lúc mở form) → 400 `VALIDATION_ERROR` `fields.categoryId` "Danh mục không tồn tại. Vui lòng chọn lại." → UI tải lại danh sách danh mục.
- Ảnh không phải JPG/PNG (theo magic bytes, kể cả đổi đuôi) → 415 `UNSUPPORTED_FILE_TYPE`; ảnh > 5MB → 413 `FILE_TOO_LARGE`; sai field/multipart hỏng → 400 `INVALID_UPLOAD`.
- Upload Storage lỗi → 502 `UPLOAD_FAILED`, không ghi DB. Ghi DB lỗi sau khi upload → xoá object vừa upload, không để object mồ côi.
- Sản phẩm đã bị xoá ở tab khác → 404 `PRODUCT_NOT_FOUND`.
- Quá 60 lần thêm/sửa trong 15 phút → 429 `TOO_MANY_REQUESTS`.
- Lỗi mạng/server → thông báo thân thiện, giữ dữ liệu và ảnh đã chọn để thử lại.

## Dữ liệu & validate
- Tên: bắt buộc, NFC + trim + gộp khoảng trắng, 1–100 ký tự, không unique.
- Giá: số nguyên VND, chỉ chữ số (không dấu chấm/phẩy, không số 0 đầu), **1 – 100.000.000**. Hiển thị dạng "199.000 ₫".
- Danh mục: bắt buộc, uuid của danh mục tồn tại.
- Ảnh flat lay: bắt buộc khi thêm, tuỳ chọn khi sửa; JPG/PNG (magic bytes); ≤ 5MB; **kích thước tối thiểu 400×400 px (cả chiều rộng và cao; Q10), không kiểm tra tỷ lệ**; field multipart `image`; 1 ảnh/sản phẩm; path `{product_id}/flatlay-{epoch_ms}.{jpg|png}` do server đặt.
- `imageUrl`: signed URL TTL 1 giờ; ký lỗi → `null`.

## API
Chi tiết: `design/flows/product-management.md` mục 1–3, 8; tóm tắt `design/flows/README.md` mục 3.

| Method | Path | Kết quả |
|--------|------|---------|
| GET | `/api/admin/products?categoryId=` | 200 `{ products: AdminProduct[] }` (mới nhất trước, không phân trang) |
| GET | `/api/admin/products/:id` | 200 `{ product }` · 404 `PRODUCT_NOT_FOUND` |
| POST | `/api/admin/products` (multipart `name`, `price`, `categoryId`, `image`) | 201 `{ product }` · 400 · 413 · 415 · 429 · 502 |
| PUT | `/api/admin/products/:id` (multipart, `image` tuỳ chọn) | 200 `{ product }` · 400 · 404 · 413 · 415 · 429 · 502 |
| DELETE | `/api/admin/products/:id` | 200 `{ id }` · 404 |
| GET | `/api/categories/:id/products` (Task 7, mọi user đã đăng nhập) | 200 `{ category, products: [{ id, name, price, imageUrl }] }` (cũ nhất trước) · 404 `CATEGORY_NOT_FOUND` |

## Acceptance Criteria (kết hợp sprint backlog Task 5, 6, 7)
- Admin thêm sản phẩm kèm ảnh thành công; object nằm đúng bucket `products`, đúng path; row lưu `image_path`.
- File sai định dạng / quá 5MB / nhỏ hơn 400×400 px bị từ chối với thông báo rõ; không tạo row, không để object.
- Lỗi DB sau khi upload không để lại object mồ côi.
- Sửa thông tin hoạt động; thay ảnh thì ảnh cũ bị xoá khỏi Storage; không thay ảnh thì ảnh giữ nguyên.
- Xoá sản phẩm có xác nhận, xoá cả row và object; sau test `storage.objects` của bucket `products` không còn object thừa.
- Danh sách lọc theo danh mục đúng; dữ liệu còn sau reload.
- User thường không gọi được API admin (403). User đã đăng nhập đọc được `GET /api/categories/:id/products`; response không có `image_path`, `created_at`, `updated_at` hay trường nội bộ.

## Phi chức năng
- Bảo mật: `requireAuth` → `requireAdmin` → limiter → multer (không nhận file của request không có quyền); kiểm tra magic bytes, không tin mimetype/tên file; bucket private, chỉ service role.
- Tái sử dụng: tổng quát hoá upload/xoá/ký URL của avatar theo `bucket` và tên field, không sao chép; API avatar giữ nguyên hành vi.
- Hiệu năng: ký URL danh sách theo lô (`createSignedUrls`); danh sách < 500 ms ở quy mô demo; xem lại phân trang khi > 200 sản phẩm.
- Không log buffer ảnh, tên file gốc.
- UX: xem trước ảnh trước khi lưu, chặn bấm lặp, giữ dữ liệu khi lỗi, ô giá chỉ nhận số với gợi ý đơn vị VND; desktop + mobile cơ bản.
