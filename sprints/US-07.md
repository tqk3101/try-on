# US-07: Thêm vào giỏ ngay trên màn hình thử đồ

> Bản đề xuất 2026-11-18, chờ người dùng chốt Q23, Q25, Q26, Q31, Q33 (`design/flows/README.md` mục 7). Nếu chốt khác mặc định, cập nhật file này trước khi code.

## Bối cảnh
- Epic: Mua sắm & Giỏ hàng (Epic 4).
- Vai trò: Người mua (mọi user đã đăng nhập, kể cả admin – Q31).
- Mục tiêu: Đang xem ảnh mình mặc sản phẩm thì bấm "Thêm vào giỏ" ngay, không rời phòng thử đồ.

## Phạm vi
- Nút "Thêm vào giỏ" trong `ProductPanel` ở `/try-on/:categoryId` (chỗ đã chừa ở Sprint 3, Q20), áp cho sản phẩm **đang hiển thị**.
- Giỏ lưu ở server theo tài khoản (Q23, bảng `cart_items`); thêm sản phẩm đã có → tăng số lượng +1 (Q26), tối đa 10 chiếc/dòng, 50 dòng/giỏ (Q25, Q33).
- Badge số lượng giỏ ở header (`MainLayout`, `AccountMenu`, `LandingHeader` khi đã đăng nhập), dẫn tới `/cart`.
- Ngoài phạm vi: chọn size/màu, tồn kho, giỏ cho khách chưa đăng nhập, thêm vào giỏ từ landing hay nơi khác ngoài phòng thử đồ, cập nhật lạc quan.
- Thiết kế chi tiết: `design/flows/cart-and-orders.md` mục 2–4, 6; bảng `design/database/schema.md` mục 15; API tóm tắt `design/flows/README.md` mục 3.

## Luồng chính (happy path)
1. User ở `/try-on/<váy>`, đang xem sản phẩm 2/6 "Váy lụa" (ảnh thử đồ đã hiện, hoặc vẫn đang tạo).
2. Bấm "Thêm vào giỏ" → nút khoá, nhãn "Đang thêm…" → `POST /api/cart/items { productId }`.
3. 201 → toast "Đã thêm Váy lụa vào giỏ." kèm link "Xem giỏ hàng"; badge header = `cart.itemCount`.
4. User tiếp tục bấm mũi tên/vuốt sang sản phẩm khác bình thường.
5. Bấm "Thêm vào giỏ" lần nữa với "Váy lụa" → 200 → toast "Váy lụa đã có trong giỏ, số lượng: 2."

## Luồng lỗi cần xử lý
- Token hết hạn → 401 → `apiClient` xử lý chung (`/login?redirect=…&reason=expired`).
- Sản phẩm vừa bị admin xoá → 404 `PRODUCT_NOT_FOUND` → toast lỗi + tải lại danh sách sản phẩm (như luồng 404 của thử đồ).
- Đã 10 chiếc → 409 `CART_QUANTITY_LIMIT` → toast "Mỗi sản phẩm chỉ đặt tối đa 10 chiếc."
- Giỏ đủ 50 dòng → 409 `CART_FULL` → toast lỗi + link "Xem giỏ hàng".
- Bấm liên tục → 429 `TOO_MANY_REQUESTS` (60/phút); 500 / mất mạng → toast `error.message`, nút bấm lại được.
- Hai tab cùng thêm một sản phẩm → server cộng dồn đúng (không lỗi `23505` ra ngoài).

## Dữ liệu & validate
- `productId`: bắt buộc, uuid, sản phẩm tồn tại.
- `quantity` (tuỳ chọn, mặc định 1): number nguyên 1–10; tổng sau cộng dồn ≤ 10.
- Không gửi/nhận giá từ client để tính; giá hiển thị lấy từ `cart` server trả.

## API
| Method | Path | Kết quả |
|--------|------|---------|
| POST | `/api/cart/items` `{ productId, quantity? }` | 201 `{ cart, item }` (dòng mới) · 200 `{ cart, item }` (cộng dồn) · 400 · 404 `PRODUCT_NOT_FOUND` · 409 `CART_FULL` / `CART_QUANTITY_LIMIT` · 429 |
| GET | `/api/cart` | 200 `{ cart }` (nạp badge khi đăng nhập / khôi phục phiên / tab lấy lại focus) |

## Acceptance Criteria
- Nút "Thêm vào giỏ" hiện ở phòng thử đồ cho sản phẩm đang xem, ở mọi trạng thái ảnh (đang tạo, thành công, lỗi, hết lượt); desktop + mobile 375px không cuộn ngang, vùng chạm ≥ 44px.
- Thêm sản phẩm mới → 1 dòng `cart_items` quantity 1, badge tăng 1, toast đúng tên; thêm lại → quantity 2, response 200.
- Thêm khi đã 10 → 409 `CART_QUANTITY_LIMIT`, DB không đổi; dòng thứ 51 → 409 `CART_FULL`.
- Thêm vào giỏ không làm thay đổi trạng thái phòng thử đồ (vị trí `?product=`, ảnh, poll, phím ←/→ vẫn hoạt động).
- Giỏ còn nguyên sau reload, đăng xuất rồi đăng nhập lại, mở trên trình duyệt khác cùng tài khoản.
- User A không đọc/sửa được giỏ của user B (mọi truy vấn theo `sub`).
- Response không chứa `image_path`, `profile_id`.

## Phi chức năng
- Bảo mật: `requireAuth` → `cartLimiter` → validate; chỉ backend truy cập `cart_items` (RLS bật, GRANT `service_role`).
- Hiệu năng: POST/GET < 500 ms ở quy mô demo; ký URL ảnh theo lô.
- UX/A11y: nút là `<button>` có chữ (không chỉ icon), trạng thái đang gửi có chữ; toast `aria-live`; không cướp focus khỏi vùng phòng thử đồ.
